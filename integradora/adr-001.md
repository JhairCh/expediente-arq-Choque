# ADR - 001 : Uso del patron Observer para notificar al estudiante

## Contexto seria que:

El sistema del comedor debe notificar al estudnate cuando su pedido pas al estado "PREPARADO"
Para eso necesitamos una forma de comunicar este cambio sin hacer que la clase Pedido dependa directamente de una implementacion especifica de notificacion.

## La Decision 

Se utilizara el patron Observer.
Ya que la clase Pedido sera la encargada de notificar a los observadores cuando cambie su estado a PREPARADO.

Entonces el Estudiante actua como observador y este recibira la notificacion.

## Alternativas

Cabe decir que Pedido podria llamar directamente a un metodo del Estudiante si, pero no se eligio porque aumentaria el acoplamienteo entre las clases.

## strategy
este permite cambiar algoritmos o las formas de realizar una operacion, pero en este caso el problema que tenemos es notificar cuando ocurre un cambio de estado.

## Factory

Factory sirve principalmente para crear objetos y no resuelve directamente el problema de notificar al estudiante.

## Consecuencias
POSITIVAS
-Pedido puede notificar sin depender directamente de una clase concreta.
-Se puede agregar otros observadores en el futuro.
-La responsabilidad de recibir la notificacion queda separada.

NEGATIVAS
-Se agregan una interfaz y clases adicionales.
-El diseño es un poco mAs complejo que una llamada directa.
